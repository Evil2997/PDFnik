# data-contracts.md — Pydantic-модели и межсервисные контракты

Загружается безусловно вместе с `core-python.md`. На него ссылается
router-таблица в шапке `core-python.md` — там сказано, при какой работе
этот файл открывать.

Читается в дополнение к `core-python.md`, когда задача касается
Pydantic-модели, пакета контрактов (Schemes) или сообщения очереди.

## 1. Граница сервиса — только через модель

Сырой `dict`, полученный из очереди/внешнего API/файла, живёт не дольше
одной строки — до `Model.model_validate(...)`. Всё, что после, работает
с типизированной моделью, не с `data.get(...)`. Это касается любой новой
границы, не только уже существующих очередей.

```python
job = TxtTranscribeJob.model_validate(data)  # первая строка обработчика
```

## 2. Каждая точка обмена данными между сервисами имеет модель — без исключений

Публикация анонимного `dict` в очередь/HTTP-ответ запрещена. Новая
очередь/эндпоинт начинается с модели в общем пакете контрактов, а не с
кода, который её потом формализует "когда будет время".

## 3. Имена протокольных констант — в пакете контрактов, не в Settings

Имя очереди, топика, ключа события — часть контракта между сервисами,
такая же, как поля модели. Это не конфигурация per-environment (не
Settings), а константа протокола:

```python
class Queues:
    TXT_TRANSCRIBE = "txt.transcribe"
    TXT_DONE = "txt.done"
```
Опечатка в строковом литерале не ловится ничем; опечатка в имени
атрибута класса — `AttributeError` на импорте.

## 4. Модель — для данных, пересекающих границу; не для внутрипроцессного состояния

Реестр в памяти процесса (таймеры, локальный кеш, session-объекты,
которые никогда не сериализуются) — `dataclass`/обычный класс с `dict`
внутри, не `BaseModel(extra="allow")` с доступом через setattr/getattr.
Признак нарушения: `arbitrary_types_allowed=True` ради того, чтобы
запихнуть нерасходуемый объект (`asyncio.Task`, сокет, соединение) в
поле модели — сигнал, что модель здесь не нужна.

## 5. Временный код совместимости — с условием удаления, а не датой в уме

Поддержка старого формата сообщения (легаси-алиасы полей, старый kind,
опциональные поля из прошлой версии контракта) сопровождается
комментарием с **условием**, при котором ветку можно удалить (например
"remove once Schemes >= vX.Y задеплоен во всех сервисах и DLQ пуст"), а
не держится бессрочно как "на всякий случай". Условие, а не абсолютная
дата — потому что дата в комментарии сама протухает и превращается в
такой же мусор, как обычный TODO.

## 6. StrEnum vs Literal

- `StrEnum` — если значение пересекает границу сервиса (лежит в
  очереди/API), сериализуется как строка, и/или имеет три и более
  осмысленных значения, к которым естественно привязать поведение
  (`.is_terminal()` и т.п. позже).
- `Literal[...]` — если значение живёт только в сигнатуре одной
  функции/метода, не пересекает границу и служит для проверки одного
  конкретного вызова mypy.
- Голый `str` для закрытого множества значений — не использовать
  (частный случай "без голых дженериков" из core-python.md).

## 7. `model_config` указан осознанно, не по умолчанию

- Модели-контракты между сервисами — `extra="forbid"`: опечатка в поле
  продюсера обязана ловиться на консьюмере как `ValidationError`, не
  теряться молча.
- Модели, принимающие внешний ввод от клиента, которым может понадобиться
  прислать поля будущей версии — `extra="ignore"` осознанно, с
  комментарием почему именно ignore, не forbid.

## 8. Конфигурация окружения — только через `Settings` (pydantic-settings)

Новая env-переменная добавляется в `Settings`, не читается напрямую
через `os.environ`. У каждого поля — `description` и, где применимо,
границы (`ge`/`le`). Обоснованный `# type: ignore[call-arg]` на месте
инициализации `Settings()` — норма для pydantic-settings с обязательными
полями из env, но всегда с кодом ошибки в скобках, не голый ignore.

## 9. Примитивное поле/параметр со смыслом — `TypeAlias`, не голый тип

Поле или параметр типа `str`/`float`/`int`/`list[str]`/`list[float]`/
`list[int]`, чей смысл нельзя прочитать по самому типу (`user_id: str`,
`scores: list[float]`) — именованный алиас через `typing.TypeAlias`, имя
которого описывает данные, а не их Python-тип:

```python
UserId: TypeAlias = str
ScoreList: TypeAlias = list[float]

def get_scores(user_id: UserId) -> ScoreList: ...
```

`typing.NewType` не используется для этого случая — он даёт отдельный
runtime-конструктор и номинальную типизацию, что здесь не нужно;
`TypeAlias` достаточно для читаемости сигнатуры и проверки mypy без
дополнительной обёртки в рантайме.

Размещение алиаса:
- Алиас, переиспользуемый в 2+ сервисах или являющийся частью контракта
  между сервисами (пересекает границу очереди/API) — в
  `PDFnik-Schemes/pdfnik_contracts`, рядом с моделями, которые его
  используют.
- Алиас, специфичный для одного сервиса (используется только внутри
  одного репозитория) — в этом же репозитории, не выносится в общий
  пакет контрактов заранее "на будущее".

Не подпадает под правило: параметр, чей смысл уже однозначно читается из
имени и локального контекста одной короткой функции (`width_px: int` в
теле, где рядом `height_px: int` — оба уже говорят сами за себя) —
алиас здесь не добавляет информации, только шум сигнатуры.
