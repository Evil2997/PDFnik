# python-bot.md — PDFnik-TelegramBot (aiogram)

Названо `python-bot.md`, чтобы не путаться с `.claude/rules/
service-telegram-bot.md` (корень, карта файлов и фактов, не языковой
стандарт) — разные файлы, разное назначение, разная папка.

Загружается безусловно вместе с `core-python.md`. На него ссылается
router-таблица в шапке `core-python.md` — там сказано, при какой работе
этот файл открывать.

Читается в дополнение к `core-python.md` (и `async.md` при пересечении)
при работе в PDFnik-TelegramBot.

## 1. Redis-ключ — только через билдер-функцию одного модуля

Ни одна f-строка с Redis-ключом не существует за пределами модуля-
билдера (`redis_keys.py` или аналог) — везде импорт функции, не сборка
ключа по месту. Частный случай DRY из core-python.md, применённый к
Redis-ключам конкретно.

```python
def pdf_session(chat_id: int) -> str:
    return f"pdf_session:{chat_id}"
```

## 2. Внешние данные от Telegram — санитизируются на входе по единому паттерну

- MIME-тип файла → расширение — через явную таблицу соответствий с
  дефолтом на случай отсутствия данных, не эвристику на месте.
- Имя файла на диске — генерируется (`uuid4().hex + ext`), оригинальное
  имя от пользователя никогда не становится частью пути на файловой
  системе (path injection).
- Регулярные выражения для разбора апдейтов (URL, форматы) —
  прекомпилированы на уровне модуля, не внутри хендлера на каждый вызов.

Новый код, принимающий файл/URL/текст из апдейта — переиспользует этот
паттерн, не изобретает свой на месте.

## 3. FSM-состояния и `callback_data` — типизированы

Набор состояний (`StatesGroup`) и вариантов `callback_data` — `StrEnum`
(см. `data-contracts.md`, п.6: пересекает границу от Telegram, значений
обычно ≥3), не сравнение голых строк по хендлерам. Сборка/разбор
`callback_data` — через один модуль-билдер/парсер, аналогично
Redis-ключам (п.1), не `data.split(":")` в каждом хендлере отдельно.

## 4. Хендлер верхнего уровня — диспетчер, не место для сценарной логики

Хендлер, получающий апдейт с разными возможными комбинациями полей
(voice/audio/document/playlist-ссылка), определяет тип сценария и
делегирует в отдельные функции модуля с явными зависимостями (см.
core-python.md, DI и "логика не в замыканиях"), не ветвится вглубь сам
на 100+ строк.

## 5. Фоновый таймер, привязанный к пользователю — во владеющем реестре с защитой от гонок

Таймер (тишины, паузы, TTL-напоминания) — не голый `create_task`
(см. `async.md`, п.3), а запись в реестре, ключевом по `chat_id`/
`user_id`, с отменой предыдущего таймера при создании нового и
версионированием состояния во внешнем хранилище, если решение о
срабатывании должно быть устойчиво к рестарту процесса (см. `async.md`,
п.5 про разделённое состояние).
