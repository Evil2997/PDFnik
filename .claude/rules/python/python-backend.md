# python-backend.md — PDFnik-Backend (FastAPI + RabbitMQ/faststream + SQLite)

Названо `python-backend.md`, не `service-backend.md` — в `.claude/rules/`
(корень) уже есть файл `service-backend.md` с другим содержанием (карта
файлов и фактов, не языковой стандарт); одинаковое имя в разных папках
создаёт неоднозначность при обращении по короткому имени.

Загружается безусловно вместе с `core-python.md`. На него ссылается
router-таблица в шапке `core-python.md` — там сказано, при какой работе
этот файл открывать.

Читается в дополнение к `core-python.md` (и `data-contracts.md`/`async.md`
при пересечении) при работе в PDFnik-Backend.

## 1. Внешний путь/ключ файла — только через guard от path traversal

Любой код, принимающий имя файла/storage-ключ извне (из очереди, из тела
запроса, из query-параметра) — резолвит путь и проверяет принадлежность
корневой директории с понятной ошибкой при выходе за границу:

```python
def resolve_storage_path(storage_key: str, root: Path) -> Path:
    candidate = (root / storage_key).resolve()
    try:
        candidate.relative_to(root.resolve())
    except ValueError as e:
        raise ValueError(f"storage_key points outside root: {storage_key}") from e
    return candidate
```
Правило применяется к каждому новому месту, принимающему путь/ключ
извне, без исключений "это же внутренний сервис".

## 2. Внешний движок (транскрипция, рендеринг, любой тяжёлый пайплайн) — за портом

Оркестрация пайплайна (порядок шагов, бизнес-решения) не смешивается с
вызовом конкретной библиотеки/системы в одной функции — интерфейс
(`Protocol`) на границе, оркестрация принимает реализацию параметром
(конкретизация DI-правила из core-python.md для доменных пайплайнов
Backend). Это единственный способ протестировать оркестрацию без
поднятия реальной инфраструктуры.

## 3. Ретраи очереди — через переиздание с attempt-счётчиком, не native retry брокера

Job несёт `attempt`/`max_attempts` в своей модели; при неудаче —
переиздание с `attempt + 1`, после исчерпания — публикация ошибки (со
стабильным кодом, см. core-python.md п.8) в исходящую очередь и явный
DLQ. Схема наблюдаема и не зависит от специфичной настройки брокера.

## 4. Дедупликация одновременной работы по ключу — с проверкой identity при освобождении

Блокировка in-flight операции по бизнес-ключу (например, ключу кеша
транскрипции) — двухступенчатая: guard-lock защищает структуру локов,
освобождение проверяет, что освобождается именно тот лок, которым
владели, а не любой лок с тем же именем, появившийся позже. Наивное
"удалить лок по ключу" в releaser — гонка.

## 5. SQLite-миграция — атомарна

`BEGIN EXCLUSIVE` + явный `COMMIT`/`ROLLBACK`. `executescript` не
используется для многошаговых миграций — implicit commit внутри ломает
атомарность при падении между шагами. Каждая миграция сопровождается
комментарием, что произойдёт при падении на середине.

## 6. FastAPI-роут — тонкая обвязка, не место для бизнес-логики

Тело функции-роута — вызов сервиса/репозитория и маппинг результата в
response-модель (частный случай core-python.md п.7 про
`register_*`-обвязку). `response_model` указан явно на каждом роуте.
Доменное исключение не течёт в HTTP-слой как есть — конвертируется в
`HTTPException` со стабильным кодом (core-python.md п.8), `str(e)`
клиенту не отдаётся.

## 7. `Settings` — единственная точка конфигурации сервиса

Каждое поле — `Field(default=..., description=...)`, границы (`ge`/`le`)
там, где применимо. Новый конфигурируемый параметр сервиса — сначала в
`Settings`, использование — вторым шагом, не наоборот.
