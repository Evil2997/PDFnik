# async.md — asyncio

Загружается безусловно вместе с `core-python.md`. На него ссылается
router-таблица в шапке `core-python.md` — там сказано, при какой работе
этот файл открывать.

Читается в дополнение к `core-python.md`, когда задача касается
`async def`, консьюмеров, фоновых задач или моста поток↔loop.

## 1. Блокирующий I/O не выполняется в event loop

`async def`, тело которого делает синхронный файловый/сетевой I/O —
не async, а ложь в сигнатуре: на время операции блокируется весь процесс,
включая несвязанные хендлеры/таймеры. Файловый I/O — через
`asyncio.to_thread`, CPU-bound — через `run_in_executor`. Если операция
всегда быстрая и фиксированного размера — можно оставить синхронной, но
это осознанный выбор с комментарием, не умолчание по инерции сигнатуры
`async def`.

```python
async def save_bytes(self, data: bytes, path: Path) -> None:
    await asyncio.to_thread(self._write, path, data)

def _write(self, path: Path, data: bytes) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_bytes(data)
```

## 2. Мост "поток → loop" — один разрешённый способ

`asyncio.run_coroutine_threadsafe(coro, loop)` + `fut.result(timeout=...)`
с именованным таймаутом (см. правило про магические числа в
core-python.md) и логом при неудаче. `loop` захватывается через
`asyncio.get_running_loop()` **до** ухода в поток/executor, не внутри
потока-исполнителя — иначе `get_event_loop()` в чужом потоке либо кинет,
либо вернёт не тот loop.

## 3. У каждой `asyncio.create_task` есть владелец

Голый `create_task(...)` без сохранённой ссылки — запрещён: сборщик
мусора может отменить задачу без ссылок, её нельзя остановить при
shutdown, а исключение внутри всплывёт как "Task exception was never
retrieved" в произвольный момент. Задача — либо в реестре с явным
жизненным циклом (создание/отмена предыдущей/обработка
`CancelledError`), либо в переменной с понятным временем жизни, либо в
`TaskGroup`.

## 4. `CancelledError` пробрасывается дальше, не проглатывается

`except asyncio.CancelledError:` для очистки ресурсов — обязательно с
`raise` в конце (или отсутствием `except` вовсе, только `finally`).
Проглоченный `CancelledError` ломает кооперативную отмену — задача не
остановится при shutdown, хотя вызывающий код думает, что остановилась.

## 5. Состояние, разделённое между памятью процесса и внешним хранилищем — задокументировано

Если часть состояния механизма живёт в памяти процесса (`asyncio.Task`,
локальная переменная), а часть — во внешнем хранилище (Redis/БД) —
в докстринге модуля/класса явно фиксируется, что переживает рестарт
процесса, а что нет, и почему это приемлемо. Это не должно
восстанавливаться чтением кода каждый раз заново.

## 6. Fail-open / fail-closed — явный выбор с комментарием на месте

Любое решение "что делать при недоступности внешней зависимости
(Redis/БД/сеть) в некритичном пути" — с комментарием, какой режим
выбран и почему. Молчаливый `except Exception: return True/False` без
пояснения неотличим от случайной ошибки при ревью.
