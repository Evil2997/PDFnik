# Архитектурные правила PDFnik

## Запреты
- Микросервисы НЕ импортируют друг друга напрямую. Никаких `from PDFnik-Backend import ...` в боте и наоборот.
- Вся коммуникация — только через RabbitMQ (очереди: txt.transcribe, txt.done, pdf.generate, pdf.send и т.д.).
- Общая библиотека `PDFnik-Schemes` содержит только Pydantic-модели и константы. Никакой бизнес-логики, вызовов БД, RabbitMQ.

## Факты
- Бэкенд и бот монтируются общий Docker volume `files_storage` (путь внутри контейнеров `/data_files_storage`).
- Redis используется ботом для сессий (`pdf_session:{chat_id}`) и блокировок дедупликации.
- Чистильщик `PDFnik-files_cleaner` запускается по расписанию (TTL) и удаляет старые файлы из `files_storage`.

## При работе с кодом
- Если меняешь модель в `PDFnik-Schemes`, **обязательно** обнови версию (команда `/bump-schemes`).
- После изменения общих схем — проверь совместимость бэкенда и бота (перезапусти тесты обоих сервисов).
