# Правило: перевод строк в коде

Проблема: при переводе user-facing строк (например "неизвестно" → "unknown")
юнит-тесты, проверяющие точное значение строки, ломаются молча.
Пример из истории репо: test_youtube_metadata_model.py падал на
assert m.duration_str == "неизвестно" после того как код стал возвращать "unknown".

Правило:
- Перед переводом ЛЮБОЙ строки в коде — grep по tests/ на старое значение.
- Если тест проверяет эту строку — обнови тест в ТОМ ЖЕ коммите.
- Никогда не оставляй тесты красными после перевода.
- В conftest / фикстурах тоже проверь захардкоженные ожидаемые строки.
- Отмазка "это pre-existing на master, не моя работа" НЕ принимается, если
  падение вызвано незаконченным переводом строк. Такие тесты надо ЗАВЕРШИТЬ
  переводить, а не списывать как чужую проблему. Конкретно сейчас: 3 падающих
  теста в duration_str (unknown/неизвестно) — это незаконченный перевод,
  их надо доделать.
