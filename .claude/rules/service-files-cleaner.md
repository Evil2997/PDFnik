# Чистильщик временных файлов
- Процесс с циклом: `run_cleanup_round()` каждые `CHECK_INTERVAL_SECONDS`
  (дефолт 600с); `ONESHOT=true` — один проход и выход (для внешнего
  планировщика вместо внутреннего цикла).
- Чистит только `images/` и `pdf/` под `FILES_ROOT` (дефолт
  `/data_files_storage` — общий volume `files_storage`, см.
  `architecture.md`). Про деление на "бэкенд"/"бот" сервис не знает, это
  один общий путь. Раздельные TTL: `IMAGES_TTL_HOURS` (дефолт 1ч),
  `PDF_TTL_HOURS` (дефолт 24ч).
- Критерий удаления — только возраст файла (`mtime` vs TTL). Проверки, не
  используется ли файл активной задачей бэкенда/бота, НЕТ. Риск: если где-то
  в пайплайне обработка файла может занять дольше TTL, чистильщик удалит
  файл, который ещё используется. Понижать TTL ниже дефолтов без проверки
  этого сценария не стоит.
- Логирует `scanned`/`deleted`/`errors` (счётчики, `CleanupStats`) — размер
  в байтах не логируется и не считается.
