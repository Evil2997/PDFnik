## Шаг 1 — Исправить правило

**RootModel полностью убрать из правила.** Это была самостоятельная инициатива
агента в предыдущей сессии, пользователь её не давал, она не нужна.

**Новая формулировка (без исключений):**

`dict`/`tuple` любой формы — это `BaseModel`. Для случая, где раньше
предполагалось исключение «ключ — это данные, произвольное множество»
(`_MIME_DEFAULT_EXT`, `EXTRACT_PROMPTS`, `MODE_LABELS`): ключ никогда не
остаётся ключом словаря — он становится полем модели, а сама структура —
`list[BaseModel]`.

```python
# плохо — ключ несёт смысл, но спрятан в dict
_MIME_DEFAULT_EXT: dict[str, str] = {"audio/mpeg": "mp3", "audio/wav": "wav"}

# хорошо — ключ и значение оба явные поля
class MimeExtension(BaseModel):
    mime_type: str
    extension: str

MIME_DEFAULT_EXTENSIONS: list[MimeExtension] = [
    MimeExtension(mime_type="audio/mpeg", extension="mp3"),
    MimeExtension(mime_type="audio/wav", extension="wav"),
]
```

Если в конкретном месте использования нужен O(1)-доступ по ключу — собрать
обычный `dict` из списка в точке использования
(`{m.mime_type: m.extension for m in MIME_DEFAULT_EXTENSIONS}`), а не хранить
его как каноническую форму данных.

**Исправление по категории C из прошлого обзора:** `checks` в `health.py` —
три заранее известных ключа (`rabbitmq`, `files_storage`, `runs_db`) — это не
lookup на данных, это структура с именованными полями. Переносится в
категорию A (dict/tuple → BaseModel), не под новое правило про
`list[BaseModel]`.

**Все словари с открытым ключом из прошлого обзора** (`EXTRACT_PROMPTS`,
`MODE_LABELS` в обоих репо, `_MIME_DEFAULT_EXT`) переводятся по новой схеме —
`list[BaseModel]`.

Обнови текст правила в `pydantic-over-primitives.md` с этой формулировкой,
покажи финальный текст файла.

## Шаг 2 — Алиасы для примитивов (напоминание из прошлой сессии)

Все примитивные поля/параметры типов `str`, `float`, `int`, `list[str]`,
`list[float]`, `list[int]`, чей смысл не читается из самого типа — через
`TypeAlias` (`UserId: TypeAlias = str`), не `NewType`.

Размещение:
- переиспользуемые в 2+ сервисах или входящие в контракт между сервисами —
  в `PDFnik-Schemes/pdfnik_contracts`;
- специфичные для одного сервиса — в этом же репозитории.

Если правило про размещение алиасов ещё не записано в `data-contracts.md`
как отдельный пункт — запиши его там в том же стиле, что и остальные правила
(описание класса случаев, не привязка к конкретным файлам/строкам).
